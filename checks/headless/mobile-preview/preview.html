2. 统一规则（手机 = 屏宽小于 640px；电脑、平板照现在）

  1. 顶栏变矮：64 → 48px，标题字小一号。
  2. 页头介绍、区块说明收成标题后的「i」：灰色介绍句、Dispatch 橙色那句、「Each window shows two messages…」「CCL's schedule from Discord…」这类，手机上不显示，点标题后的 i 再看（弹出小框）。
  3. How to use 一律放页面最底、收起（现在 Settings 几页放在最上面）；区块里的「How to use — xxx」链接 / 框也收进那个 i。
  4. 提示条压成一行：黄框、红框只显示第一行，后面「More」点开看全文；纯操作提示（「Drag columns to reorder」「Click a Bus # to…」）手机上不显示，因为手机上本来就拖不了。
  5. 次要按钮收进「⋯」：Columns、Export CSV、Show hidden rows、Upload、Auto-fill 这类，手机上收进一个 ⋯ 菜单；日期、搜索、Save、Send 这些主要操作照旧露在外面。
  6. Settings 页先给列表：「+ Add …」表单、Extra columns 这类设置区默认收起成一行，点开再填。
  7. 统计卡排一行：Tracking 这种 3–4 个数字的卡片，手机上排成一行小卡。
  8. 步骤框排一行：Dispatch 的 ① Assign / ② Send 手机上并排、去掉下面那行小字。
  9. 右下角 ↑↓ 手机上不显示：手机本来就能直接滑，两个圆键一直盖在内容上。
  10. 页面不能比屏幕宽：只有表格自己左右滑，整页不晃（Content Studio 现在会晃）。
  11. 做成共用组件：i、⋯、一行提示条、收起的表单都放进 components/ui，现有页面换上，以后的新页面照着用就自动符合，再写进 CLAUDE.md 当规矩。

3. 两种方案

方案 A：收起（推荐）

上面 11 条都做；shortcut 条留着，压成一行 36px，左右滑。东西都还在页面上，只是收起来。

内容平均提前 300–800px；员工找东西的位置和电脑版一样。

方案 B：再精简

A 全做，再把 shortcut 条整条收进顶栏的 ★ 按钮（点开是同一组捷径）。

再多出约 50px；代价是捷径要多点一下，和电脑版不一样。

5. 要 Annie 定的事

题 1　用方案 A 还是方案 B？

哪里：全站手机版，每页顶上的 shortcut 条（Dashboard、Manifests、Dispatch… 那排捷径）。

现在：每页都占 49px 一整行，加上顶栏共 129px。

  • A：留着，压成一行 36px，左右滑。和电脑版一样的位置。
  • B：收进顶栏的 ★ 按钮，点开再选。再多出约 50px 给内容，但捷径要多点一下。

推荐 A：员工每天靠这排捷径跳页，藏起来反而慢；省下的主要空间来自说明和表单，不在这一行。

题 2　Settings 页的「+ Add …」表单手机上默认收起？

哪里：Settings › Vehicles、Pickup Locations、Products 等有新增表单的页。

现在：表单整个摊开在列表上面（Pickup Locations 有 2486px），列表要滑到第二到第四屏。

  • A：手机上收成一行「+ Add Vehicle」，点开才出表单；列表排第一屏。
  • B：照现在摊开。

推荐 A：手机上多半是查，不是新增。电脑版照旧摊开。

题 3　右下角 ↑↓ 两个圆键手机上要不要？

哪里：全站右下角回顶 / 到底的蓝色圆键。

现在：每页都盖在内容上（截图右下角）。

  • A：手机上不显示（手机直接滑就行）。
  • B：留一个 ↑（回顶），去掉 ↓。
  • C：照现在两个都留。

推荐 A。

题 4　黄框 / 红框提示手机上压成一行？

哪里：例如 Manifests 的「⚠️ 1 row on this page comes from data frozen before Aug 16, 2026 (marked Legacy). Booking questions and most Trip / Booking fields are empty for it.」、Content Studio 的「⚠️ Every Save changes the live text right away…」。

  • A：只显示第一行，后面「More」点开看全文。
  • B：照现在全文显示。

推荐 A。红色报错（保存失败、读不到）不压，照旧全文。
